# Weather for macOS: feature traceability

This document maps every feature of the GTK/C app in `src/` to the C code that defines it, the Swift code that implements it in `macos/`, and the Swift tests that pin it. It also lists every documented difference with its consequence and its DECISIONS row, the places where the README and the C code disagree (the code is the authority), and every C test case that no Swift test cites.

Sources: the C sources and tests in `src/`, the cartography maps of the port run, every unit's debrief and verdict, and `macos/`. Status: built by work unit U35 on 2026-10-23; refreshed after the final verdicts of U13 (#79), U27 (#71), U32, U33 (#73) and U34 (#72) and the U37 phase-A strict census (#75).

How to read the tables:

- **C source** is the `path:line` where the rule is written (a constant, a string literal or the contract comment). Further ranges are named in the feature text.
- **Swift test** names `Suite/testName` in `macos/WeatherCoreTests`, separated by ` · `. Each named test cites the C case it ports (`// C: /path`) or is an executor test of that C rule. `view-only` means **no automated test pins the row**: the Weather app target has no test bundle and the app is never launched in the run, so these rows rest on the view source and on the maintainer's manual check (D9).
- Every upstream unit has passed its final verification — including U13 (#79), U27 (#71), U32, U33 (#73) and U34 (#72) — so every row is final.
- Parity claims are qualified. 'C literals ported' means the expected values of the Swift tests are the C tests' literals. Numeric parity of the blend and the formatting is measured by scratch differentials against the unmodified C built with `clang -O1 -ffp-contract=off`: the Swift port is **byte-identical to the C built without FMA contraction**. A C build that fuses multiply-adds (clang's default `-ffp-contract=on`, or gcc on FMA targets) changes only `wx_forecast_now`'s six interpolated 'now' fields: about 95 % of the differing values by 1-6 ulps, a tail up to about 3,072 ulps near cancellation (relative error at most 6.4e-13), and one 5e-324 vs 0.0; hours, quarters, days and errors never differ (U21 guardrail verifier).
- DoD 6 (security model) and DoD 7 (refresh policy) are **not stated as met** here. DoD 6's retry clause is met at the client level only, and the rate-limit reactions of DoD 7 hold only for 429 heads the client sees; rows S10, S11 and R09 and the transport differences D-T05..D-T26 give the qualifiers. The HTTP contract sweep (155 rows: 68 same, 11 fixed now, 52 pinned difference, 14 not testable, 10 cross-reference) enumerates the C contract; it is not a fuzz of the response grammar, so inputs outside its rows may still differ.

Counts: 108 feature rows; 28 transport, 15 platform and 28 model differences routed by DECISIONS rows, plus 14 differences accepted at unit verification and recorded by #68; 28 README-vs-code items; 1030 C test paths, 885 cited by a Swift test, 145 in the exclusion table (7 of them are mentioned only in 'Not ported' comments or a cross-reference note, which census.py counts as cited, so census.py reports 892 cited and 138 excluded).
